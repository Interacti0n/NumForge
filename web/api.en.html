Usage and API

JavaScript sends expressions to the local server. The C application parses and evaluates them with BigInt, BigRational or BigDecimal, then formats the result.

Exact expressions retain integers and reduced fractions. Decimal output for a recurring fraction uses the current precision; the default display has 10 decimal places.

What you can enter

ElementExamples
Integers and decimals42, -1.5, 1,5, .25, 1.
Scientific notation1.25E-3, 6E4; uppercase E is required
Operators+, -, *, /, ^; power has the highest binary-operator precedence and postfix operations bind more tightly. Real exponents must be integers; if either operand is complex, principal noninteger and complex powers are also supported.
Parentheses and signs(2 + 3) * 4, -(2.5E-1) * 8

% is not supported yet.

Variables

  • Names contain 1–31 letters a–z or A–Z, without accents, digits, spaces or underscores. For example, x, speed and myValue are valid; x1, my_value and rýchlosť are not.
  • Names are case-sensitive: x and X are separate variables. Existing function names and their aliases, the constant e, the imaginary unit i and ans are reserved. Uppercase I can be a variable.
  • Enter x = 2/3 and confirm with Enter or Calculate. Previews do not store anything. Another assignment, such as x = x + 1, replaces the value; it does not store a formula that recalculates when other variables change.
  • Store a variable before using it. Multiply names explicitly: x*y; xy is one name. Each calculation supports only one top-level assignment; x = y = 2 and (x = 2) + 1 are not supported.
  • A session stores up to 32 variables, including exact fractions, complex numbers and values with units. The × button beside a variable deletes it and frees a slot.
  • ans holds the last confirmed result; previews do not change it. Clearing history keeps variables and ans. A new session, session expiration or server restart clears them; variables are not saved permanently.

Constants use stored 500-decimal-place values at ordinary precision and are calculated dynamically for larger requests. Standalone lowercase e means Euler's number: 5e means 5 * e and 1e3 means 1 * e * 3. Scientific notation always uses uppercase E: 5E-1 is 0.5 and 1E3 is 1000. Trigonometry uses one RAD/DEG selector whose choice is remembered by the browser.

The RAD/DEG selector is on the right beside precision settings. Function signatures and argument hints appear on hover, keyboard focus or touch. Connection failures and unexpected server responses can be retried with Enter; these are distinct from expression errors.

Function calls

Enter complex numbers as 2 + 3i, 2 + 3*i or complex(2;3). Lowercase i is the imaginary unit: i^2 = -1; it cannot be assigned. Exact fractions stay exact; addition, subtraction, multiplication, division and integer powers are supported. Separate adjacent ASCII names with *: x*i multiplies, while xi is one variable name.

re(z) returns the real part, im(z) the imaginary part, conj(z) the complex conjugate and abs(z) its magnitude. For example, re(2+3i) = 2, im(2+3i) = 3, conj(2+3i) = 2-3i and abs(3+4i) = 5. Components and exact rational magnitudes remain exact. arg(z) returns the principal argument in radians in (−π, π]; arg(0) is undefined. Even in DEG, arg(i) is approximately 1.5707963268. For real numbers, im(x) = 0 and conj(x) = x.

exp(z), e^z and pow(e;z) support complex exponents through exp(a+bi) = exp(a)·(cos(b)+i·sin(b)), always in radians. This is approximate; e^(π*i) approaches −1 and may display a small nonzero imaginary residual. Other bases accept noninteger and complex exponents when either operand is complex: z^w and pow(z;w) use exp(w·ln(z)), the principal logarithm branch and radians. For example i^i ≈ 0.2078795764 and (-1+0i)^(1/2) ≈ i. Integer powers stay exact. Zero to zero is one; zero to a positive real exponent is zero; negative real and nonreal exponents of zero fail. Approximate powers may retain tiny residuals; identities across branch cuts do not generally hold. Settings select Cartesian, trigonometric or exponential display; copying uses stored components through complex(re;im). Complex arguments to other real-only functions and complex unit conversions remain unsupported; extract a real component explicitly with re or im.

sqrt(z) or √(z) returns one principal complex square root: sqrt(3+4i) = 2+i, sqrt(-1+0i) = i. The real component is nonnegative; the imaginary component follows the input sign, with a positive imaginary root on the negative real axis. For example, sqrt(-3-4i) = 1-2i. Rational roots stay exact; other roots are approximate. Zero maps to zero. Plain sqrt(-1) still reports a real-domain error; enter a complex value explicitly.

ln(z) returns the principal complex natural logarithm ln(|z|) + i·arg(z). For example, ln(-1+0i) is approximately 3.1415926536*i and ln(i) approximately 1.5707963268*i, even in DEG. The imaginary component is always in radians in (−π, π]; the negative real axis uses +π, while approaching from below gives −π. ln(0) and ln(0*i) are undefined. Plain real ln(-1) remains an error; log(z) uses base 10 and log(z;b) uses ln(z)/ln(b) when either argument is complex. For example log(i) ≈ 0.6821881769*i, log(-1+0i;i)=2 and log(-i;i)=-1. Zero input and bases 0 or 1 are invalid; negative and nonreal bases are allowed in this complex path. Results remain approximate even when displaying a real number. Bases close to one amplify numerical error; principal log and power are not general inverse identities across branch cuts. Complex ln results are numerical approximations; exact fractions are projected to decimal components at working precision for this operation.

qty(value; "unit") creates a value carrying a unit. For example, qty(5; "m") * qty(5; "m") = 25 m² and qty(1; "km") + qty(500; "m") = 1.5 km. Variables and ans retain units; incompatible sums fail. Products, quotients and integer powers compose dimensions. A temperature minus another temperature gives an interval; adding two temperature points is an error. Use explicit qty() calls; 5m is not a unit literal.

convert(value; "from"; "to") returns a number: convert(90; "km/h"; "m/s") = 25. Use quoted, case-sensitive catalogue IDs such as m2, degC, MB or MiB. Only compatible units can be converted; exact conversions retain fractions. The Units page lists the catalogue. The numeric result of this convert call carries no unit when saved in a variable or ans. Values created with qty retain their units.

sqrt(x) or √(x) is the square root for x ≥ 0; cbrt(x) also accepts negative x. root(x;n) takes an integer degree from 1 to 10000; negative x requires odd n. Exact finite roots remain exact; other roots use max(34, N+4) significant digits (full output: 34), then output formatting. Time and memory limits still apply.

gcd(a;b) and lcm(a;b) return the non-negative greatest common divisor and least common multiple of integers. gcd(0;0)=0; lcm with zero is 0. mod(a;b) is the integer remainder with the dividend's sign: mod(-7;3)=-1; a zero divisor is an error. isqrt(n) is the floor square root of a non-negative integer: isqrt(15)=3. Decimal spellings of whole values, such as 4.00, are accepted.

npr(n;r) calculates permutations and ncr(n;r) combinations without repetition. Both arguments must be integers satisfying 0 ≤ r ≤ n.

Also available: abs(x) (absolute value), sign(x) (−1, 0 or 1), min(a;b;…) and max(a;b;…) (at least two arguments). They compare evaluated values without additional rounding.

sum(a;b;…) and product(a;b;…) are exact; mean(a;b;…) divides the exact sum by the value count and rounds only a recurring result to working precision. Each function accepts 1 to 256 arguments.

variance(a;b;…) is population variance and stdevp(a;b;…) is population standard deviation; both divide by the value count n. Sample stdev(a;b;…) divides by n−1 and requires at least two values. Intermediates stay exact until final division or root.

median(a;b;…) returns the exact median. geomean(a;b;…) accepts non-negative values and harmean(a;b;…) only positive nonzero values.

floor(x), ceil(x), and trunc(x) return an integer. round(x) rounds to an integer and round(x;n) to integer n decimal places using half-even; negative n selects tens, hundreds, and larger powers of ten.

Names use lowercase letters only, parentheses are mandatory, and ; separates arguments. Comma remains a decimal separator: pow(1,5;2) = 2.25. At most 256 arguments per call.

pow(x;y) works like x^y (real integer exponents use the reciprocal when negative; explicit complex operands also allow principal noninteger or complex powers); factorial(n) works like n! (integer n from 0 to 10000).

Also available: exp(x), ln(x), common log(x), and log(x;b) with base b. Real logarithm arguments must be positive; a custom real base must be positive and different from 1. ln also accepts explicit nonzero complex inputs as described above.

sin(x), cos(x), tan(x), asin(x), acos(x), and one-argument atan(x) are active. Inverse calls also accept arc and arcus names, such as arcsin(x), arcussin(x), arctan(x), and arcustan(x). The RAD/DEG selector applies to the whole expression; inverse calls return the selected unit. asin/acos require x from -1 to 1, and tan(90) is an error in DEG mode.

Hyperbolic sinh, cosh, tanh, asinh, acosh, and atanh are independent of RAD/DEG. Their inverse calls also accept both longer forms, such as arcsinh(x), arcussinh(x), arccosh(x), and arcuscosh(x). acosh requires x ≥ 1 and atanh requires -1 < x < 1. Function search recognizes every alias as well as the prefixes arc and arcus.

radians(x) and degrees(x) are explicit conversions independent of the selector. The BigDecimal library API always uses radians. √(x) aliases sqrt(x).

exp is one name, not a product of letters. Standalone e remains a constant: e(2) = e*2, 1e3 = 1*e*3, 1E3 = 1000. Separate adjacent names with *; ee and esin are not constants or functions; in a session they can refer to previously stored variables.

Automatic precision and cache

Output: Auto uses 10 decimal places, Full skips final rounding, and Custom shows a field for 0–10000 places. Full does not mean infinite working precision. Language switching preserves the mode and custom value.

The separate notation selector offers Auto, plain, scientific (1.23E+45), mathematical (1.23 × 10^45) and Fraction output. Auto shows an exact fraction when its denominator is at most 10000, its text is at most 16 characters, and it is at least two characters shorter than the decimal display. Otherwise, after rounding, Auto uses scientific when |exponent| ≥ 10 or plain output would exceed 80 characters. Fraction shows an exact non-integer as a/b up to 16 characters; longer fractions and approximate results use Auto decimal notation. Integers remain without /1. Output is limited to 65536 bytes. Mathematical output copies in parser-compatible E form when it fits the input limits. Changing notation does not change the stored value or ans.

You choose output decimal places and notation. Working precision remains automatic: max(34, N+4) significant digits, or 34 for full output. The server retains the last successful numeric result per browser session, for up to eight clients. Matching working contexts only reformat; changes to working precision recompute the expression. Proven precision-independent expressions such as 10000! can be reformatted across precisions without evaluation. Reload reads the retained session; session eviction requires starting again. This does not certify every final digit under cancellation.

Optional HTTP parameters after precision/angle: &client=32_hex_digits&revision=N. Before client, &notation=auto|plain|scientific|math|fraction selects output notation; mathematical responses add copy in E form, or null when it exceeds limits. Client is exactly 32 lowercase hexadecimal digits; revision increases from 1 to 9007199254740991. Successful responses then also include the boolean cached. Without these parameters the API is stateless. The identifier is not authentication.

When the result displays an exact fraction, a smaller line beneath it shows an approximate decimal value marked ≈, with up to 10 places. Very small values may use scientific notation. Copying and history keep only the exact fraction.

Random values

rand() draws in [0,1), rand(x) in [0,x) for x > 0, and rand(x;y) in [x,y) for x < y. Each occurrence draws separately from a 34-place decimal grid. Repeated previews keep their draws; a new Enter draws again. This is not cryptographically secure.

ans and history

Preview does not change ans. Enter, Calculate or = confirms a successful result and appends history. ans holds the internal value, not the rounded display; higher precision cannot recover lost approximation digits. Before the first confirmation ans is undefined. Errors preserve state.

The Session panel has History and Variables tabs with internal scrolling. History retains the last 16 confirmations. Variables lists all up to 32 stored names with their last confirmed assignment display; clicking inserts the name, while × deletes the variable and reclaims capacity without changing ans or history. Entries are numbered by confirmation order; the number keeps increasing as older entries leave the list. Each entry stays on one line; a long preview ends with three dots, while the full result remains available for insertion or through its copy button. Clicking an entry inserts its result at the input cursor, or at the end when there is no cursor. Language changes and guide navigation in the same tab keep the session, history, numbering, input and settings. Reloading reads the existing server session. New session explicitly resets it. Clear history keeps ans and variables. The server retains eight sessions, evicting the oldest; reload after expiration. Restarting the server also loses in-memory sessions. CLI commands are history and reset. C clears only input.

The browser appends &action=start (empty body), followed by requests with &action=preview or &action=commit. Start performs no calculation. Repeating the latest successful confirmation with the same revision, expression and settings returns the original result. On an uncertain response Enter retries the same request; a new confirmation waits. Older or conflicting revisions are rejected. Requests without action keep the original behavior.

Delete a variable through HTTP: POST /api/evaluate?precision=10&angle=rad&client=32_hex_digits&revision=N&action=delete-variable, with a text/plain body containing only its name, for example x. Use an existing session and a fresh revision. Success returns {"ok":true,"result":""}. If the response is lost, retry the same name/revision before another request. There is no API yet for listing all variables, retrieving history or explicitly resetting the existing session; start a new empty session with a new client ID. This command is not a mathematical expression.

Exact division retains a reduced fraction, including recurring quotients. Decimal display rounds according to the selected settings. (1E34+1)/1-1E34 = 1.

1.2.3, 1,2,3 and 2 3 are errors, not products. (2)3, 3!2 and 2²3 remain valid. Implicit multiplication has the same precedence as * and /: 6/2(1+2) = 9.

Exact rational arithmetic retains (1/3)*3-1 = 0. Output places do not guarantee whole-expression accuracy for approximate functions such as irrational roots. Full output does not undo their rounding.

Output precision

Decimal places: 0–10000, default 10; applies to the mantissa in scientific notation. Non-terminating division uses max(34, N+4) significant digits. Full output skips final rounding, not 34-digit division. 1E-40 / 1 stays 1E-40. Constants use the same working precision; intermediate results can still be rounded.

The whole calculation has a 5 s budget, including parsing and output, checked inside expensive numeric loops. Cancellation is cooperative, not a hard real-time guarantee. Limits: 64 MiB cumulative allocations, 128 KiB per allocation, 65536 output bytes, depth 256. Exceeding them returns TLE or value too large. Public numeric APIs do not have these application limits.

Local HTTP interface

A local client sends UTF-8 expressions to POST /api/evaluate?precision=10&angle=rad. Port is 8765 or selected with --port. Precision is 0–10000 or full; angle is rad or deg. Input is limited to 4096 bytes (HTTP 413 if exceeded) and must arrive completely within 2 s (HTTP 408). Individual bytes do not restart the deadline.

POST /api/evaluate?precision=10&angle=rad HTTP/1.1
Host: 127.0.0.1:8765
Content-Type: text/plain; charset=utf-8
Content-Length: 6

π / 2

HTTP/1.1 200 OK
{"ok":true,"result":"1.5707963268"}

Content-Length is required; without it the server returns HTTP 411. A foreign browser Origin gets HTTP 403. Invalid expressions or precision return HTTP 400 JSON with ok, error, status, and a one-based column. Out-of-memory calculation failures return HTTP 500.

Public C API

The public types are BigInt, BigDecimal and BigRational. They are opaque: create them with *_create(), release them with *_destroy(), and release strings from *_to_string() with free().

BigInt

#include <numforge/bigint.h>

  • Status: bigint_status_to_string
  • Lifecycle and text: bigint_create, bigint_destroy, bigint_copy, bigint_set_string, bigint_to_string
  • Comparison: bigint_compare, bigint_is_zero, bigint_is_one, bigint_is_negative, bigint_is_even, bigint_is_odd
  • Arithmetic: bigint_abs, bigint_negate, bigint_add, bigint_sub, bigint_mul, bigint_div, bigint_mod, bigint_div_mod, bigint_pow
  • Number theory: bigint_gcd, bigint_lcm, bigint_factorial, bigint_permutation, bigint_combination, bigint_isqrt, bigint_is_probable_prime, bigint_is_perfect_square
  • Bits: bigint_and, bigint_or, bigint_xor, bigint_not, bigint_shift_left, bigint_shift_right

Division truncates toward zero. bigint_div_mod requires distinct objects for quotient and remainder. Bitwise AND/OR/XOR accept non-negative values only. Probable-prime and perfect-square checks return status separately from their bool result.

BigDecimal

#include <numforge/bigdecimal.h>

  • Status: bigdecimal_status_to_string
  • Lifecycle and text: bigdecimal_create, bigdecimal_destroy, bigdecimal_copy, bigdecimal_set_string, bigdecimal_to_string
  • Comparison: bigdecimal_compare, bigdecimal_is_zero, bigdecimal_is_negative
  • Exact operations: bigdecimal_abs, bigdecimal_negate, bigdecimal_add, bigdecimal_sub, bigdecimal_mul
  • Aggregates: exact bigdecimal_sum and bigdecimal_product; bigdecimal_mean with significant digits and a rounding mode
  • Statistics: bigdecimal_median, bigdecimal_geometric_mean, bigdecimal_harmonic_mean, bigdecimal_variance_population, bigdecimal_standard_deviation_population, bigdecimal_standard_deviation_sample
  • Further operations: signed integer powers, roots, bigdecimal_exp, bigdecimal_ln, bigdecimal_log10, bigdecimal_log, significant division, bigdecimal_sin, bigdecimal_cos, bigdecimal_tan, inverse trigonometry, hyperbolic and inverse hyperbolic functions, bigdecimal_set_constant, bigdecimal_set_constant_significant and formatting
  • Rounded operations: bigdecimal_rescale, bigdecimal_floor, bigdecimal_ceil, bigdecimal_trunc, bigdecimal_round, bigdecimal_div; modes TOWARD_ZERO, AWAY_FROM_ZERO, FLOOR, CEILING, HALF_UP, HALF_EVEN with the BIGDECIMAL_ROUND_ prefix

BigRational

#include <numforge/bigrational.h>

Stores exact reduced fractions with a positive denominator. It provides exact arithmetic, comparison, conversion from BigInt and BigDecimal, and conversion to BigDecimal with explicit precision and rounding. A denominator of one prints as an integer.

Mutating operations return a status code and leave the destination value unchanged on failure. Full signatures are in the headers and a more detailed overview is in docs/API.md.

Session and conversion HTTP API

GET /api/session?client=ID reports revision, capacities and ans availability. Read all variables with /api/session/variables, calculator history with /api/session/history, and a saved value with /api/session/value?client=ID&name=ans. Lists support offset/limit, revision pinning with at, and full=1 for lossless values. Revisions are decimal strings.

POST /api/session?client=ID&revision=N&action=clear-history keeps ans and variables; reset clears all session values; release frees values and marks the session closed. These calls have an empty body. GET /api/functions lists function names, aliases and arities.

Confirm conversions through POST /api/conversions?client=ID&revision=N&action=commit&from=km&to=m with the expression body. Read or retrieve saved records with GET /api/conversions and clear them with action=clear. Converter revisions are independent; replay returns the original saved value without reevaluation. Snapshots distinguish exact integers/fractions, approximations and Quantity dimensions/units/context. The complete contract is in docs/reference/SESSION_HTTP_API.md.
